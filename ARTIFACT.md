# Artifact

This repository holds the RTL of the 2x2 manycore (Hermes NoC, RV32E cores, DDMA), the UCX-OS kernel with application E, the ORCA RT-Tools Python package and the pipelines that compute the numbers of the paper from stored inputs and stored simulation logs. License: GNU AGPL v3 (`LICENSE`).

## Contents

| Path | Content |
|---|---|
| `pkt-sim/hw` | RTL: Hermes router and NoC (VHDL), RV32E core, DDMA, PE (SystemVerilog) |
| `pkt-sim/manycore_modelsim` | Top level and the Questa/ModelSim script of the 2x2 manycore |
| `pkt-sim/software/ucx-os` | UCX-OS kernel; application E in `app/weird_a.c`; release by tick of the phase model in `lib/tick_release.c` |
| `orca-rt-tools/rttools` | ORCA RT-Tools; `rttools/paper` holds the pipelines |
| `apps` | Task graphs, mappings and platforms (application E in `apps/synthetic-app-e`, CAR in `apps/shi-2010`) |
| `experiments/ch7` | Contraction criteria on the random graphs (ORT/GCM, ORT/GDE); clustering of CAR and application E |
| `experiments/exp23` | Application E: stored Questa log, analysis and check; `make paper` simulates again |
| `experiments/figures` | Data of the article visuals (contraction criteria, Gantt, response per iteration, flow table) |
| `experiments/zll` | Zero-load latency testbench of the Hermes NoC (GHDL) |
| `experiments/car-v-rtl` | CAR-V on the 4x4 manycore: UCX-OS application generated by `rttools.ucxgen`, stored Questa log of run CV, analysis against the phase model and check |
| `experiments/car-full` | CAR as a whole (four periods, two cycles) with the general phase model (`rttools/bench_t/multirate.py`): analysis flow and check; UCX-OS application `car_full` (time-triggered tasks) and the targets of its RTL run |
| `experiments/wcet` | Static task costs t(v) (`rttools.wcet`: static WCET analysis of the PE image plus the kernel costs) against the stored runs H and CV2; application WCET-E (`apps/wcet-e`, input-dependent bodies) for the RTL |
| `experiments/multiapp` | CAR-V and application E on one 4x5 NoC (`rttools.multiapp`): one link schedule for the packets of both applications, one clock, R_bound per application; UCX-OS image `carv_e` of both applications (`rttools.ucxgen compose`) and the analysis of its RTL run per application |

## Requirements

| Use | Software |
|---|---|
| Pipelines (`make -C experiments`) and Python tests | Python 3.10 or later with `orca-rt-tools/requirements.txt`; pytest for the tests; GHDL 4 (tested with 4.1.0, mcode backend) for the zero-load latency (`zll`) |
| New RTL simulation (`make -C experiments/exp23 paper`) | Questa Sim (tested with 2025.3) or ModelSim, riscv64-elf-gcc 12.2.0, GNU make |

## Simulation runs

`make paper` writes `RUN_INFO` with the commit, the state of the work tree (`clean`, `dirty`, `archive`, `nogit`), the tag and a SHA-256 of the simulated sources (`experiments/exp23/README.md`). The run that the paper reports comes from a clean checkout at a tag:

```
git checkout <tag>
make -C experiments/exp23 paper REQUIRE_CLEAN=1 ENV_SETUP="<commands that load Questa and riscv64-elf-gcc>"
```

With `REQUIRE_CLEAN=1`, `simulate.sh` stops before the build when the tree has changes or no tag. A simulation server without access to the repository receives `git archive --prefix=orca/ -o orca.tar <tag>`; the archive carries the commit hash in `experiments/exp23/VERSION`, and `RUN_INFO` records `repo_state=archive`.

## Release by tick

Release by tick (`lib/tick_release.c`, kernel and application built with `-DUCX_APP_IRQ4 -DUCX_APP_TICK -DUCX_TICK_RELEASE`): the release generator fires on every PE with a task (`app/<app>.sim`: `RELEASE_MASK`, `TICK_RELEASE=1`), the release interrupt counts the phases, and the tick hook of the kernel wakes the tasks whose phase has come. Each task of `weird_a.c` and of the applications of `rttools.ucxgen` waits for the tick of phase j + n(v) before it reads the input of iteration j, so it runs at most once per phase, as the phase model assumes. The stored runs A to H, CV, CV2 and MA come from the data-driven release (a task serves every iteration whose packets are in its queue): `weird_a_data` (Makefile of UCX-OS) and `rttools.ucxgen --release data` give that code, and the analyses of those logs take `--release data`. `python -m rttools.paper.phasecheck <metrics.json>` (`make phase-check` in `exp23`, `car-v-rtl` and `multiapp`) checks the executions per phase and the CPU per phase of a run against the model.
