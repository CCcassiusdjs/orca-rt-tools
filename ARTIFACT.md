# Artifact

This repository holds the RTL of the 2x2 manycore (Hermes NoC, RV32E cores, DDMA), the UCX-OS kernel with application E, the ORCA RT-Tools Python package and the pipelines that compute the numbers of the paper from stored inputs and stored simulation logs. License: GNU AGPL v3 (`LICENSE`).

## Simulation runs

`make paper` writes `RUN_INFO` with the commit, the state of the work tree (`clean`, `dirty`, `archive`, `nogit`), the tag and a SHA-256 of the simulated sources (`experiments/exp23/README.md`). The run that the paper reports comes from a clean checkout at a tag:

```
git checkout <tag>
make -C experiments/exp23 paper REQUIRE_CLEAN=1 ENV_SETUP="<commands that load Questa and riscv64-elf-gcc>"
```

With `REQUIRE_CLEAN=1`, `simulate.sh` stops before the build when the tree has changes or no tag. A simulation server without access to the repository receives `git archive --prefix=orca/ -o orca.tar <tag>`; the archive carries the commit hash in `experiments/exp23/VERSION`, and `RUN_INFO` records `repo_state=archive`.

## Release by tick

Release by tick (`lib/tick_release.c`, kernel and application built with `-DUCX_APP_IRQ4 -DUCX_APP_TICK -DUCX_TICK_RELEASE`): the release generator fires on every PE with a task (`app/<app>.sim`: `RELEASE_MASK`, `TICK_RELEASE=1`), the release interrupt counts the phases, and the tick hook of the kernel wakes the tasks whose phase has come. Each task of `weird_a.c` and of the applications of `rttools.ucxgen` waits for the tick of phase j + n(v) before it reads the input of iteration j, so it runs at most once per phase, as the phase model assumes. The stored runs A to H, CV, CV2 and MA come from the data-driven release (a task serves every iteration whose packets are in its queue): `weird_a_data` (Makefile of UCX-OS) and `rttools.ucxgen --release data` give that code, and the analyses of those logs take `--release data`. `python -m rttools.paper.phasecheck <metrics.json>` (`make phase-check` in `exp23`, `car-v-rtl` and `multiapp`) checks the executions per phase and the CPU per phase of a run against the model.

Interrupts: every interrupt handler of UCX-OS leaves interrupts disabled until the return of `_isr` (`pkt-sim/tests/rtl/tb_cpu_irq.vhd` tests this behavior). `dispatch()` of the tick does not enable them, `yield()` restores the state of its caller and a task starts through `_task_start` (`hal.c`). `-DUCX_ISR_NESTING` builds the kernel of the stored runs A to H, CV, CV2, MA, W1 and CF, whose handlers enable interrupts before that return (`ISR_NESTING=1` in `simulate.sh` and `build_sw.sh`). `simulate.sh` writes `isr=no_nesting` or `isr=nesting` in `RUN_INFO`; the analyses copy it to `clock.isr` of `metrics.json`, `nesting` for a `RUN_INFO` without the line, and the references of the stored runs state `clock.isr = nesting`. Return of `_isr` and `_interrupt_set` (`crt0.s`, every image): the return of `_isr` tests its return address, and `_interrupt_set(0)` reads `IRQ_STATUS` back until it is 0 (`tb_cpu_irq.vhd` modes 2 and 3). `CRT0` of `simulate.sh` and `build_sw.sh` selects the `crt0.s`: `guard_readback` (default), `guard` (return test only: `car_full` of tag r11-rc4, run CF3) or `plain` (the `crt0.s` up to tag r11-rc3, the default with `ISR_NESTING=1`); the assembler symbols are `UCX_ISR_NO_RETURN_GUARD` and `UCX_ISR_NO_DI_READBACK` (`UCX_ASDEFS` of the UCX-OS Makefile). `simulate.sh` writes `crt0=<value>` in `RUN_INFO`; the analyses copy it to `clock.crt0`, `plain` for a `RUN_INFO` without the line (`guard` for `car_full` of r11-rc4), and the references of the stored runs up to tag r11-rc3 state `clock.crt0 = plain`.

Runs of tag r11-rc3 (release by tick and the kernel without nested interrupts, `isr=no_nesting`, Questa 2025.3, riscv64-elf-gcc 12.2.0): TG and TH (application E at 500 MHz and 434.912 MHz, 20 ms; `experiments/exp23/logs/{TG,TH}.*`, `make -C experiments/exp23 check-run`, values.tex in `build/results_{TG,TH}`), TCV (CAR-V at 380 MHz, 11.5 ms; `experiments/car-v-rtl/logs/TCV.*`, part of `make -C experiments/car-v-rtl check`), TMA (carv_e at 434.912 MHz, 11.5 ms; `experiments/multiapp/logs/TMA.*`, `make -C experiments/multiapp check-tma`) and W2 (WCET-E at 500 MHz, 10 ms; `experiments/wcet/logs/W2.*`; `make -C experiments/wcet check` runs W2 and `analyze-r11c check-r11c`, the static t(v) of the images of TH, TCV and W2 against these runs, values.tex in `experiments/wcet/build/r11c`). ## Premise (ii) and the release guard

The link schedule of the flow keeps premise (ii) of the paper (the release handler of each phase ends on every PE before the tick of that phase, Section 6.5): `rttools/modules/routing/router.py` (`release_guard`, constants `RELEASE_LEAD_CYCLES`, `ISR_ENTRY_CYCLES`, `RELEASE_SECTION_CYCLES`, `RELEASE_END_CYCLES`, `RELEASE_HANDLER_CYCLES`) rejects the injection instants that break it in AGS (`rttools/modules/backend/ags/search3.py`, `GUARD`, `GUARDS`), and `rttools.paper.ttflow.premise_release` checks a link schedule against the terms of its image. The margins of Sections 7.1 and 7.7 are the field `premise_release` of `experiments/tt/build/metrics.json` (one entry per run) and of `experiments/automotive/build/metrics.json`. `RTTOOLS_RELEASE_GUARD=off` rebuilds the link schedules of the stored runs CF5 and UH, whose tables the generator built before the guard.
