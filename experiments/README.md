# Experiments

`make` in this directory runs the pipelines of `DIRS` (Python pipelines that take seconds and the zero-load latency testbench of the NoC, about 30 s) and checks each result against the reference stored in its directory; `make <dir>` runs one of them. The long runs have their own targets. `ARTIFACT.md` at the root of the repository maps the numbers of the paper to these commands.

| Directory | Content | `make` | Long targets |
|---|---|---|---|
| `ch6` | Tables 6.5, 6.6, 6.7 (ORT/FNS) | Synthetic-Application-D and DCT-Verify | `make car` (hours) <!-- anon:drop-line --> |
| `ch7` | Contraction criteria (ORT/GCM, ORT/GDE) on the random graphs; clustering of CAR and of application E | Graphs with \|V\| = 20 to 100 | `make graphs full` (about 20 minutes), then `make stats`; `make car` (seconds) |
| `exp23` | Application E on the 2x2 manycore: CPU time per iteration, response time, flows, Gantt | Stored Questa log of run F against `reference_head.json`; minimum frequency of application E with o_i = L0 + 20 (m + 1) (`make frequency`, the default occupancy of rttools) against `reference_frequency.json` and with o_i = L0 (`make frequency-l0`) against `reference_frequency_l0.json` | `make paper` (Questa and riscv64-elf); stored runs G (500 MHz) and H (434.912 MHz, clock of the flow) of tag r10-rc1 with iteration markers and flit times: `make LOG=logs/G.events.txt REF=reference_G.json OUTDIR=build/results_G` (and H) |
| `figures` | Data of the article visuals: contraction criteria on the example graph; Gantt, response per iteration and flow table of application E from the stored log of run F | Both, against `reference_contraction.json` and `reference_exp23.json` | |
| `car-v` | CAR-V, the vision subgraph of CAR on the time scale of application E (`apps/car-v`, generated from `apps/shi-2010`): ORT/GCM on 16 clusters, Spiral Mapping on the 4x4 mesh, f_CPU, frequency search, R_bound, flow windows, packets and heap per PE | Generator against `apps/car-v/car-v.csv`; analysis flow of each cost factor and payload divisor of `config.json` against `reference.json` (seconds) | |
| `car-full` | CAR as a whole (`apps/car-full`, generated from `apps/shi-2010`: 33 tasks, 38 flows, periods 0.5 to 12.5 ms after the scale of CAR-V, cycles NAVC-OBDB-NAVC and OBDB-OBMG-OBDB) with the general phase model (`rttools/bench_t/multirate.py`): Spiral Mapping of the MAX-PROC clusters, f_CPU from the ORT/BENCH sequences over the hyperperiod, frequency search, data age of the 34 cause-effect chains, packets and heap per PE; UCX-OS application `car_full` with time-triggered tasks | Generator against `apps/car-full`; analysis flow of each cost factor and payload divisor of `config.json` against `reference.json`; generated `car_full.{c,json,sim}` and heap per PE (about 10 s) | `make build` (riscv64-elf); `make sim` (Questa, F_CLK = 478.336 MHz, the clock of run CF5 of `tt`, 64 ms); `make analyze LOG=...` |
| `car-v-rtl` | CAR-V on the 4x4 manycore (RTL): UCX-OS application `car_v` generated by `rttools.ucxgen` (with iteration markers); analysis of a run against the phase model (`rttools.paper.rtlapp`): CPU time per PE, response per iteration, packets against [r, d], network latency and header wait | Generated files and heap per PE; stored runs CV (tag r10-rc1, without markers) and CV2 (tag r10-rc2, with markers), 380 MHz, 11.5 ms, against `reference_CV.json` and `reference_CV2.json` (`make check`, seconds; not in `DIRS`) | `make sim F_CLK=380000000` (Questa and riscv64-elf, about 14.5 min); `make build` (riscv64-elf) |
| `multiapp` | CAR-V (16 PEs) and application E (4 PEs) on the 4x5 mesh, on disjoint PEs that share routers and links (`rttools.multiapp`): Spiral Mapping of each application in the order of `composition.json`, f_CPU per application, f_NoC of the union of the packets, one frequency for the platform, R_bound per application, shared links and the collisions of the schedules of each application alone; the other order, 1,000 random placements and each application alone against the flow of one application; UCX-OS image `carv_e` (`rttools.ucxgen compose`) and the analysis of a run per application (`rttools.paper.rtlapp --app`) | `reference.json`; stored maps and `carv_e.{c,json,sim}` against a new generation; heap per PE (`make`, about 20 s) | `make sim` (Questa and riscv64-elf, 443.36 MHz, the clock of run VMA of `tt`, 11.5 ms); `make build` (riscv64-elf) |
| `tt` | Model of the runs of round r11f (images with the time-triggered injection) with the defaults of rttools: the network interface of each PE as a resource and w_NI in o_i (RTTOOLS_NI unset), t(v) = max(CSV, static t(v) of the image, `wcet/costs/tt`); per application f_CPU, f_NoC, the clock of each run (phase a multiple of 16 cycles), S and F of every task, R_bound or the data age, the length of the simulation and the injection table of each clock (`rttools.paper.ttflow`) | `reference.json` (seconds) | `make tables` (link schedule and finish of every job of each run, the tables of the conferencia of `run_r11f.sh`) |
| `zll` | Zero-load latency of the Hermes NoC, L0 = 6(m+1) + p + 1; header wait at one router, at most 20 cycles | 8x3 and 2x2 meshes (GHDL, about 30 s) | `make contention` (GHDL and Python 3, 2 to 6 min), against `reference_contention.json`; `make check` runs both |

Each pipeline writes LaTeX tables, CSV files and `metrics.json` under `build/` of its directory; `make check` compares `metrics.json` with the reference of the directory and prints `match` or the differing values.

The README of each directory lists the agreement with the thesis. <!-- anon:drop-line -->

Requirements: Python with `orca-rt-tools/requirements.txt` and GHDL for `make`; `make ch7 exp23 figures car-v car-full` runs without GHDL. The Python code lives in `orca-rt-tools/rttools/paper`. `make PYTHON=<interpreter>` selects the interpreter.
